# End-to-End Check Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Turn the throwaway stdio checks into a committed end-to-end test that starts `fartt serve` the way Claude Code does, runs the trading cycle's tools in order, and proves stdout carries only the protocol (story #69).

**Architecture:** One test module, `tests/e2e/test_server_stdio.py`, marked `network`. The first test reads the server command from `.mcp.json`, appends a temporary `--assets-dir` and `--interval 1d`, and drives the server through the MCP SDK's `Client(StdioServerParameters(...))`. The second test starts the same command as a plain subprocess, speaks JSON-RPC lines to it, and asserts every stdout line is a JSON-RPC message. No production code changes.

**Tech Stack:** pytest with anyio, MCP Python SDK v2 (`mcp.Client`, `mcp.StdioServerParameters`, `mcp.types.LATEST_PROTOCOL_VERSION`), subprocess, Task.

**Spec:** `docs/specs/2026-10-08-forecast-tools-design.md` (section "4. The end-to-end check")

## Global Constraints

- The test is marked `network` (it calls Bitvavo), so `task check` and the pre-push gate deselect it; `task test:network` runs it.
- The server command comes from `.mcp.json` (`mcpServers.fartt.command` and `.args`), so the real registration is what's tested. The test only appends `--assets-dir <temp dir> --interval 1d` (argparse takes the last value of a repeated option), and runs with the repository root as the working directory, as Claude Code does.
- The cycle test lists the expected tools and calls them in trading-cycle order. Later stories (#71, #72, #73) add their tool to `EXPECTED_TOOLS` and their call to the cycle.
- The stdout test must keep stdin open until the last response arrives. Verified while writing this plan: closing stdin right after sending ends the session before a tool call, which runs on a worker thread, can answer.
- Never reference "superpowers" in code, file paths or directory structure.

## Review Focus

- **The server prints something to stdout** (a stray `print`, a progress bar, a library warning): expect the stdout test to fail and name the offending line. Pinned in Step 4, by temporarily adding a `print` to `fartt serve`, seeing the test fail, and reverting.
- **A tool is added or renamed without the test being updated:** expect the cycle test to fail on the tool list. Pinned in Step 4, by temporarily adding a name to `EXPECTED_TOOLS`, seeing the test fail, and reverting.
- **The server hangs or never answers** (e.g. a deadlock): expect the test to fail after a timeout with a clear message, not hang the run. The stdout test waits at most 120 s per response; the SDK client uses its own request timeout. The deadline covers it.
- **The registration in `.mcp.json` is broken** (wrong command or arguments): expect both tests to fail at startup. They read `.mcp.json` rather than duplicating the command.
- **The cache directory is the operator's real `assets/`:** expect the tests never to touch it. Both use a fresh temporary directory, passed with `--assets-dir`.

```python
"""
End-to-end check of the MCP server over stdio, the way Claude Code runs it:
the command and arguments come from the project's `.mcp.json`. Calls the
live exchange, so it's marked `network` (run with `task test:network`).

Each tool story adds its tool to `EXPECTED_TOOLS` and its call to
`test_trading_cycle_over_stdio`, in trading-cycle order.
"""

import json
import queue
import subprocess
import threading
from pathlib import Path
from typing import Any

import pytest
from mcp import Client, StdioServerParameters
from mcp.types import LATEST_PROTOCOL_VERSION

ROOT = Path(__file__).resolve().parents[2]
EXPECTED_TOOLS = ["get_candles"]
RESPONSE_TIMEOUT_S = 120


@pytest.fixture
def anyio_backend() -> str:
    return "asyncio"


def _server_command(assets_dir: Path) -> list[str]:
    server = json.loads((ROOT / ".mcp.json").read_text())["mcpServers"]["fartt"]
    # argparse takes the last value of a repeated option, so these override
    # .mcp.json's market interval while keeping its registration as is.
    return [
        server["command"],
        *server["args"],
        "--assets-dir",
        str(assets_dir),
        "--interval",
        "1d",
    ]


@pytest.mark.network
@pytest.mark.anyio
async def test_trading_cycle_over_stdio(tmp_path: Path) -> None:
    command, *args = _server_command(tmp_path)
    params = StdioServerParameters(command=command, args=args, cwd=str(ROOT))

    async with Client(params) as client:
        tools = sorted(tool.name for tool in (await client.list_tools()).tools)
        assert tools == sorted(EXPECTED_TOOLS)

        candles = await client.call_tool("get_candles", {"count": 5})
        assert not candles.is_error, candles.content
        content = candles.structured_content
        assert content["market"] == "BTC/EUR"
        assert content["interval"] == "1d"
        assert content["columns"] == ["time", "open", "high", "low", "close", "volume"]
        assert len(content["rows"]) == 5
        assert content["is_current"] is True
        assert content["warning"] is None


@pytest.mark.network
def test_stdout_carries_only_the_protocol(tmp_path: Path) -> None:
    messages: list[dict[str, Any]] = [
        {
            "jsonrpc": "2.0",
            "id": 1,
            "method": "initialize",
            "params": {
                "protocolVersion": LATEST_PROTOCOL_VERSION,
                "capabilities": {},
                "clientInfo": {"name": "fartt-e2e", "version": "0"},
            },
        },
        {"jsonrpc": "2.0", "method": "notifications/initialized"},
        {"jsonrpc": "2.0", "id": 2, "method": "tools/list"},
        {
            "jsonrpc": "2.0",
            "id": 3,
            "method": "tools/call",
            "params": {"name": "get_candles", "arguments": {"count": 2}},
        },
    ]
    process = subprocess.Popen(
        _server_command(tmp_path),
        cwd=ROOT,
        stdin=subprocess.PIPE,
        stdout=subprocess.PIPE,
        stderr=subprocess.DEVNULL,
        text=True,
    )
    assert process.stdin is not None and process.stdout is not None

    # Read stdout on a thread: readline() blocks, and a deadline per
    # response keeps a hung server from hanging the test run.
    lines: queue.Queue[str] = queue.Queue()
    stdout = process.stdout
    threading.Thread(
        target=lambda: [lines.put(line) for line in iter(stdout.readline, "")],
        daemon=True,
    ).start()

    try:
        for message in messages:
            process.stdin.write(json.dumps(message) + "\n")
        process.stdin.flush()

        received: list[str] = []
        while not any(json.loads(line).get("id") == 3 for line in received):
            try:
                line = lines.get(timeout=RESPONSE_TIMEOUT_S)
            except queue.Empty:
                pytest.fail(f"no response within {RESPONSE_TIMEOUT_S} s; got {received}")
            try:
                parsed = json.loads(line)
            except json.JSONDecodeError:
                pytest.fail(f"stdout carried a non-JSON line: {line!r}")
            assert parsed.get("jsonrpc") == "2.0", f"not a JSON-RPC message: {line!r}"
            received.append(line)
    finally:
        process.stdin.close()
        process.wait(timeout=30)

    responses = {json.loads(line)["id"]: json.loads(line) for line in received}
    assert set(responses) == {1, 2, 3}
    assert "error" not in responses[3]
    assert responses[3]["result"].get("isError") is not True
```
